 그림 검수 규약 — 논문을 고칠 때마다 돌린다          정한 날 2026-09-26
════════════════════════════════════════════════════════════════════

 「그림_처리_체크리스트.txt」는 **무엇을 고쳤는가**의 기록이고,
 이 문서는 **고친 뒤 무엇을 확인하는가**의 절차다. 둘은 다르다.

 왜 필요한가: 2026-09-24 하루에만 그림 결함이 여덟 개 나왔고, 여덟 개
 **전부 렌더해서 확대했을 때** 나왔다. SVG 코드나 matplotlib 인자만 읽고
 "됐다"고 보고한 것은 여덟 번 다 틀렸다. 코드가 맞아도 지면은 틀린다.

────────────────────────────────────────────────────────────────────
 0. 철칙 — 이것을 어기면 나머지는 의미가 없다
────────────────────────────────────────────────────────────────────
 · **반드시 렌더해서 눈으로 본다.** 코드만 읽고 판단하지 않는다.
 · **400% 확대로 본다.** 100% 축소본에서는 겹침·잘림이 안 보인다.
 · 고친 그림만 보지 말고 **그 그림 전체**를 다시 본다. 한 군데를 고치면
   다른 데가 밀린다(실제로 리본을 옮기니 날씨 글자와 겹쳤다).
 · 판단이 갈리면 **본문 조판(docx→PDF)까지 보고** 정한다. 그림 파일에서
   멀쩡해도 단 폭에 들어가면 달라진다.

────────────────────────────────────────────────────────────────────
 1. 도구
────────────────────────────────────────────────────────────────────
   python paper/diagram/render_svg.py <이름>     SVG → PNG
   python paper/diagram/check_glyphs.py          서체에 없는 글자 검사
                                                 (matplotlib 그림 + 원시 SVG 둘 다)
   확대 크롭 — PIL 로 잘라 키워서 본다:
     im.crop((x0,y0,x1,y1)).resize((w*4,h*4), Image.LANCZOS)
   본문 조판 확인 — PDF 를 쪽 이미지로 떠서 본다(PyMuPDF get_pixmap).

────────────────────────────────────────────────────────────────────
 2. 체크리스트 — 항목마다 실제로 난 사고가 붙어 있다
────────────────────────────────────────────────────────────────────
 [겹침]
  □ 글자가 선·상자 변·다른 글자를 관통하지 않는가
      ← availᵣ 라벨이 상자 둥근 모서리에 얹혔다
      ← "마감 강제" 글자를 간트 레일이 가로질렀다
      ← 굵은 화살표가 "CAST" 글자를 관통했다
  □ 새로 옮긴 요소가 원래 있던 것과 부딪히지 않는가
      ← "64" 리본을 옮기니 "기상 리전만 24×3=72" 와 겹쳤다

 [잘림]
  □ 액자·패널 밖으로 나간 글자가 없는가
      ← "마감 강제" 의 "제" 자가 패널 밖에서 잘렸다
      ← 각주 한 줄이 오른쪽 끝에서 닫는 괄호까지 사라졌다

 [읽힘]
  □ 채움이 너무 짙어 덩어리로 보이지 않는가
      ← LSTM 셀 20개를 검게 칠해 바코드처럼 보였다
  □ 같은 그림 안에서 같은 성격의 요소는 같은 규약으로 칠했는가
      ← 위 타일은 흰 채움+테두리인데 아래 셀만 검은 채움이었다
  □ 도형이 뜻대로 읽히는가
      ← 막대는 **바닥선에 앉아야** 값으로 읽힌다. 허공에 뜬 검은 네모는
        "왜 거기 있지"로 읽힌다(두 번 고쳤다)
  □ 곡선이 곡선으로 보이는가
      ← 진폭을 줄였더니 거의 직선이 됐다. 탄소가 크게 흔들린다는 논지 위에
        선 논문에서 예측 출력이 평평하면 그림이 논지와 반대로 읽힌다
  □ 한 행/한 묶음이 한 대상을 가리키는가
      ← 간트 한 행에 작업을 여럿 묶으니 레일이 한 줄로 이어져 어느 작업의
        창인지 구분이 안 됐다

 [범례·서체]
  □ 범례에 있는데 그림에 안 쓰인 항목이 없는가(독자가 찾다 만다)
      ← 표본에 forced 가 없어 그 색을 조건부로 뺐다
  □ check_glyphs 가 "두부로 찍힐 글자 없음" 을 내는가
  □ 한 낱말 안에서 서체가 갈리지 않는가
      ← R₁R₂R₃ 은 한글 서체인데 Rₙ 의 ₙ 만 SFNS 로 넘어갔다.
        아래첨자는 유니코드 문자 대신 tspan(sb 헬퍼)으로 찍을 것

 [캡션·조판] — 그림을 고치면 캡션과 지면도 같이 본다
  □ 캡션 마지막 줄에 한 낱말만 남지 않았는가
      ← "gCO₂/kWh다." · "자리다." 가 홀로 남았다
  □ 그림과 캡션이 같은 말을 두 번 하지 않는가
      ← 그림 안 각주와 캡션이 겹쳤다. **그림에는 범례, 캡션에는 해석**
  □ 식 번호가 다음 줄로 넘어가지 않는가
      ← "(13)" 이 "(1"/"3)" 으로 쪼개졌다
  □ 그림 높이가 늘었으면 쪽수를 다시 쟀는가

────────────────────────────────────────────────────────────────────
 3. 보고 방식
────────────────────────────────────────────────────────────────────
 · "확인했다"만 쓰지 말고 **무엇을 어떤 배율로 보았는지** 적는다.
 · 고칠 수 없으면 **왜 못 하는지 한도를 숫자로** 적는다.
     예: "라벨을 더 올리면 상자 둥근 모서리(y=128)에 걸린다. 지금이 한도다."
 · **안 되는 것을 된다고 하지 않는다.** 2026-09-24 에 "창도 빡빡하고 눈에도
   보이는 작업이 이 날 이 리전엔 없다"고 그대로 보고한 것이 옳았다.
 · 수치를 새로 뽑았으면 원자료로 검산한다. 남의 자기보고를 믿지 않는다.
