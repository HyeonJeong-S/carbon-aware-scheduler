==========================================================
J            작업 집합
R            리전 집합
H            예측 지평 = 24 (h)
슬롯 길이     1 h (탄소집약도 데이터 해상도와 일치)

작업 j 에 대해
  o_j        출발 리전
  s_j        제출 시각 (h, 실수. 정시가 아니다)
  d_j        실행 시간 (h, 실수)
  k_j        지연 등급 ∈ {1,…,5}. 1 이 가장 여유
  L_j        지연 예산 (h)
  D_j        마감 = s_j + L_j + d_j
  τ_j        실행 시작 시각        <- 결정 변수
  x_jr       배정 변수 ∈ {0,1}    <- 결정 변수

리전 r 에 대해
  cap_r      처리 용량
  η          여유율 (= 0.8)
  K_r        유효 상한 = ⌊η · cap_r⌋   (실험에서 12)
  C_r(t)     실측 탄소집약도        <- 탄소 회계에만 쓴다
  l_or       o 에서 r 로의 왕복 지연

** 예측 표기 — 발행 시각을 명시한다 (신규) **
  Ĉ_r^(τ)(t)   τ 시점에 발행된, 시각 t 에 대한 예측

  지금 본문은 Ĉ_r(t) 로만 쓰는데 그러면 발행 시각이 숨는다.
  사전 예약형과 롤링형의 차이가 정확히 "언제 발행된 예측을 쓰는가" 이므로
  이 표기 없이는 두 알고리즘을 구분해 쓸 수 없다.

C̄_j^(τ)(t')  = (1/d_j) ∫ Ĉ_r(j)^(τ)(u) du ,  u ∈ [t', t'+d_j)
              t' 에 시작할 때의 예측 탄소 평균

** 기호 충돌 정정 (미해결 항목) **
  s_j 가 5.2절에서 제출 시각, 식 (8) 에서 미배정 변수로 두 번 쓰인다.
  미배정 변수를 u_j 로 바꾼다. 단 u_j 는 아래 식 (15) 의 남은 여유와도
  충돌하므로, 미배정 변수는 z_j 로 한다.
    식 (7)(8) 의 s_j -> z_j
    식 (15) 의 남은 여유 -> u_j(t)

2. 규약 — 번호 없이 문장으로 못박을 것
==========================================================
지금 어디에도 안 적혀 있다. 이것들이 2026-09-16 버그 1의 원인이었다.

R1  후보 슬롯 격자의 기준점
    후보는 벽시계 정시 격자에 놓이되, ** 현재 시점 자체를 항상 포함한다. **

      W_j(t) = { max(t, s_j) }
               ∪ { t' ∈ ℤ : ⌈max(t, s_j)⌉ ≤ t' ≤ min(D_j − d_j, t + H) }

    첫 항이 "지금 당장 실행" 이다. 이게 없으면 제출 시각이 정시가 아닌 작업
    (거의 전부)이 다음 정시까지 밀린다. 지연 예산이 1시간 미만인 k=3,4,5
    (87,712건, 전체의 60.1%)는 그 순간 마감을 어긴다.

    W_j(t) 의 원소가 하나뿐이면 선택의 여지가 없고 즉시 실행이다.
    별도 규칙이 필요 없다 — 이 정의에서 따라 나온다.

R2  동률 처리
    score 가 같은 후보가 여럿이면 ** 가장 이른 시각 ** 을 택한다.
    현재 코드가 오름차순 순회 + 엄격부등호라 그렇게 동작한다.
    명시하지 않으면 구현마다 달라진다.

R3  r(j) 의 정의
    r(j) 는 ** 상류 단계에서 확정된 리전 ** 이다.
    비교군에 따라 o_j (홈 리전) 또는 로드밸런서 배정 결과다.
    시간 이동 단계는 리전을 바꾸지 않는다.

R4  예측 발행 시각
    사전 예약형 : Ĉ_r^(s_j)(·)  — 제출 시점에 한 번 받은 예측으로 전 윈도우 평가
    롤링형     : Ĉ_r^(t)(·)    — 평가하는 매 슬롯의 최신 예측으로 다시 평가

    ** 이 차이를 반드시 논문에 밝혀야 한다. **
    식 (11) 은 그대로지만 입력을 매 슬롯 갱신하는 것은 실질적 설계 변경이다.
    숨기면 안 되고, "미래를 안다고 가정하지 않는다" 는 강점으로 쓸 수 있다.

R5  용량 점유의 측정
    식 (3) 의 ∀t 는 연속 시각이다. 구현이 정시만 샘플링하면
    1시간을 걸치지 않는 작업들이 같은 구간에 겹칠 때 초과를 놓친다.
    실측 예: 장부 자기보고 CAL 16 vs 식 (3) 정의로 재계산 CAL 18.
    검증은 반드시 모든 시작·종료 시각에서의 이벤트 스윕으로 한다.

3. 새 식 (13)~(15) — 용량 인지 온라인 시간 이동
==========================================================
(13)  가용 자리

        n_r(t) = | { j : r(j)=r, τ_j ≤ t < τ_j + d_j } |
        a_r(t) = K_r − n_r(t)

      식 (3) 을 가용 자리 형태로 다시 쓴 것이다.
      ** 논문에 이렇게 쓸 것: "5.2절에서 식 (3) 으로 선언했으나 구현하지
         않았던 제약을 이 알고리즘이 실제로 강제한다." **

      작업을 t' 에 놓을 수 있는 조건은 시작 시점만이 아니라 실행 구간 전체다.

        feasible(j, t')  ⟺  min a_r(j)(u) ≥ 1 ,  u ∈ [t', t'+d_j)

      시작 시점만 보면 R5 의 초과를 그대로 재현한다.

(14)  희망 집합 — 지금이 남은 구간 최선인 작업

        Q(t) = { j : s_j ≤ t , τ_j 미정 }

        P_r(t) = { j ∈ Q(t) : r(j)=r ,
                   argmin_{t' ∈ W_j(t)} score_j(t') = max(t, s_j) }

      score 는 기존 식 (11) 을 그대로 쓴다. 새 점수 함수를 만들지 않는다.
      단 예측은 R4 에 따라 Ĉ_r^(t)(·) 이다.

(15)  우선순위와 선택

        u_j(t) = (D_j − d_j) − t                      남은 여유

        F_r(t) = { j ∈ Q(t) : r(j)=r , u_j(t) < 1 }   마지막 기회
        R_r(t) = P_r(t) ∖ F_r(t) 를 u_j(t) 오름차순 정렬
        S_r(t) = F_r(t) ∪ R_r(t)[ 1 … max( a_r(t) − |F_r(t)| , 0 ) ]

        j ∈ S_r(t)  ⟹  τ_j ← max(t, s_j)

      세 가지를 못박는다.

      (a) 우선순위는 ** 순수 EDF ** 다. 남은 여유만 본다.
          탄소 이득으로 정렬하면 나중에 측정할 지표로 승자를 미리 뽑는
          셈이라 순환 논리가 된다. 그리고 여유가 0 인 작업이 자동으로
          1순위가 되어 별도 예외 규칙이 필요 없다.

      (b) F_r(t) 는 ** Q(t) 전체에서 ** 고른다. P_r(t) 안에서 고르면
          "지금이 최선이 아닌" 마감 임박 작업이 누락되어 기아가 발생한다.

      (c) u_j(t) < 1 이 조건이다. u_j(t) ≤ 0 으로 하면 이미 늦은 시점에
          강제하게 되어 마감을 어긴다. 마지막으로 시작 가능한 정시는
          ⌊D_j − d_j⌋ 다.

      |F_r(t)| > a_r(t) 이면 그 슬롯은 ** 의도적으로 상한을 초과한다. **
      마감 위반 0 을 지키기 위한 선택이며, 그 건수를 용량 위반으로 따로
      집계한다. 마감 위반과 용량 위반은 서로 다른 지표이므로 합산하지 않는다.

4. 알고리즘
==========================================================
Algorithm 0 · 사전 예약형 (기존)          9줄, 산문 3줄 요약으로 대체 가능
  작업이 도착하면 그 자리에서 τ_j 를 한 번 확정하고 이후 재평가하지 않는다.
  용량을 보지 않으며 다른 작업과 상호작용이 없다.

Algorithm 1 · 슬롯 단위 롤링 재평가 (제안)    19줄, 블록으로 넣는다

  Input  : K_r , Ĉ_r^(t)(·) , H , 작업 집합
  Output : 모든 j 에 대한 τ_j

   1: Q ← ∅
   2: for t ← 0 to t_max do
   3:     Q ← Q ∪ { j : ⌊s_j⌋ = t }
   4:     for each r ∈ R do
   5:         a_r(t) ← K_r − n_r(t)                          ▷ 식 (13)
   6:         F ← { j ∈ Q : r(j)=r , u_j(t) < 1 }            ▷ 식 (15)
   7:         P ← ∅
   8:         for each j ∈ Q with r(j)=r , j ∉ F do
   9:             W_j(t) ← R1
  10:             if argmin_{t'∈W_j(t)} score_j(t') = max(t,s_j) then
  11:                 P ← P ∪ {j}                            ▷ 식 (14)
  12:         sort P by u_j(t) ascending                      ▷ EDF
  13:         S ← F ∪ P[ 1 … max(a_r(t) − |F|, 0) ]
  14:         for each j ∈ S do
  15:             τ_j ← max(t, s_j) ;  Q ← Q ∖ {j}
  16:     if Q = ∅ and 남은 도착 없음 then break

  ** 알고리즘 블록 안에 식 번호를 쓰지 않는 게 Caspian·CarbonFlex 관행이다.
     위 ▷ 주석은 이 명세 파일용이고, 논문에서는 블록 앞뒤 산문에서
     "식 (13) 에 따라..." 로 인용한다. **

5. 성질
==========================================================
정리 1 (기아 불가)
  어떤 작업도 무한히 연기되지 않는다.

  증명. t 가 한 슬롯 진행할 때 u_j(t) = (D_j − d_j) − t 는 정확히 1 감소한다.
  u_j(⌊s_j⌋) 는 유한하므로 유한한 슬롯 수 안에 u_j(t) < 1 에 도달한다.
  그 슬롯에서 j ∈ F_r(t) 이고 식 (15) 에 의해 F_r(t) ⊆ S_r(t) 이므로
  용량과 무관하게 τ_j 가 확정된다. ∎

  ** 이 보장은 식 (15) 의 합집합이 문자 그대로 무조건일 때만 성립한다.
     구현에서 "F 도 a_r(t) 안에서만" 으로 두면 깨진다. **

정리 2 (마감 위반 0)
  모든 j 에 대해 τ_j + d_j ≤ D_j 다.

  증명. W_j(t) 의 모든 원소는 t' ≤ D_j − d_j 를 만족한다(R1).
  F 편입 조건 u_j(t) < 1 에서 t ≤ ⌊D_j − d_j⌋ 이고 τ_j = max(t, s_j) 이므로
  τ_j ≤ D_j − d_j 다. 즉 마감 위반은 탐색 공간에서 배제되며
  사후 기각이 아니다. ∎

복잡도
  슬롯당   O( |Q(t)| · H + |P_r(t)| log |P_r(t)| )
  전체     O( Σ_t |Q(t)| · H )
  창 평균은 누적합 전처리로 O(1) 이다. 전처리 O(|R| · T · H).
  실측: 146,000 작업 · 8 리전 · 8,760 슬롯에서 7초 (파이썬)

  ** 무릎점 α 쪽 복잡도도 써야 한다. 지금 논문에 한 줄도 없다. **
    슬롯당 ILP 11회(α 후보 11개). 이진 변수는 슬롯 작업 수 × |R|.
    실측 평균 슬롯 작업 수 16.7, 리전 8 → 이진 변수 약 134개.
    1년 = 8,760 슬롯 × 11 ≈ 96,000 회 ILP.
    ** 실제 소요 시간을 측정해서 넣을 것. 아직 안 쟀다. **
