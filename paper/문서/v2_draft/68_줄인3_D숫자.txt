[규칙과 방법]
- %와 %p는 stats.json 의 kg 에서 다시 셈: 절감 = 100×(1 − total_carbon_kg/baseline_kg),
  %p = kg 차 ÷ 그 실행의 baseline_kg × 100, 마지막에 한 번만 반올림.
  기준 kg: 합성 28,625.462 / Azure 213,513.439 / 시드·φ·발생률 변형은 각 실행의 baseline_kg.
- 실행마다 jobs_csv(합성 jobs.csv, Azure jobs_azure.csv, 시드 variants/jobs_seed{k}.csv), rho, cap, forecast, alpha_setting, engine 을 읽어
  원고가 말한 조건과 맞춤. 특히 이번 판의 규칙 "설계 비교(표 3의 Δ)는 두 워크로드 모두 예약 없이"(4.1)를 표 3·4.4·4.7 의 모든 짝에 대어 봄.
- 같은 지연 짝은 원고 4.1 정의(실행 시간 가중 평균 왕복 지연 dw_latency_ms, 0.6 ms 안)로 다시 잼.
- 신뢰구간은 analysis/*.json 의 "d가중" 칸(이번 판 예약 없는 짝: pair_rho0_*, pair_seed*_rho0_*, pair_azure_rho0_*, alpha_pair_azure_rho0_*)과 대조,
  kg → %p 는 그 실행의 기준 kg 으로 나눔.

    - 국·영 모두 "CAST보다 많이 줄이는 둘" — 본문(4.5·기여 (3))은 "CAST 기본 운용점(무릎점)보다". CASPER 95.30 은 CAST α=1 95.65 보다 덜 줄이므로
      초록 문장만 읽으면 거짓으로 읽힐 수 있음. "기본 운용점보다" 를 넣으면 본문과 맞음.
(2) 설계 비교의 예약 조건이 원고 안에서 셋으로 갈림 — 원고 4.1 규칙은 "설계 비교(표 3의 Δ)는 두 워크로드 모두 예약 없이":
    - 표 3 Δ·4.4 첫 문단 0.96 / 0.91 / 시드 1.23~1.56 / Azure 2.53·1.99, 서론 0.96, 결론 0.96, 초록 1.0 → ρ=0 (규칙대로).
    - 4.4 무릎점 짝(71.93 대 72.08, 대기 1.47 대 2.13)과 초록의 "기본 운용점에서 같은 배출·대기 31% 짧음" → ρ=3 짝(밝히지 않음).
      예약 없는 CAST 무릎점(rho/0, 72.06%, 47.49 ms)은 있으나 같은 지연의 다시 풀지 않는 ρ=0 실행이 없음.
    - 오프라인 하한(서론 끝·4.4)과 4.7 한계 배출의 설계 짝(37.53 대 37.65, 34.84 대 33.78) → ρ=3. 4.4 하한만 "예약 3" 을 밝힘.
      4.7 짝을 표 3 의 예약 없는 짝으로 바꾸면 프랑스만 37.59 대 38.49, 대칭 34.81 대 33.62.
(3) 서론 끝 문장: "같은 왕복 지연의 고정 α에서 0.96%p(ρ=0) … 오프라인 하한에도 1.16~2.22%p로 그 설계(2.56~3.63%p)"(ρ=3) — 한 문장 안에서 조건이 바뀌는데 서론은 밝히지 않음.
    두 쪽의 "그 설계" 도 α 가 다름(표 3 짝 arrival/fixed_rho0_dw0.5444 vs 하한 짝 arrival/fixed_m0.5437).
(4) 초록 "이 이점은 2%p 안" ↔ 표 3 Azure 다시 풀지 않는 설계 Δ +2.53 (CI 1.68~3.42). 초록이 합성·Azure 를 가리지 않아 표와 어긋남.
(5) 3.2 "0.37%p(4.7절)" ↔ 표 5 Main 71.93 과 SN-24h in 3 regions 71.55: 반올림 값끼리 빼면 0.38. kg 으로는 0.373 → 0.37 이 맞음(규칙상 일치).
(6) 표 3 캡션 "두 워크로드 모두 예약 없음" ↔ 합성 위반 칸(Plan-blind 9.0–17.0, origin 0.16–0.56)은 ρ=3(시드 ρ 2~3) 실행. Azure 위반 칸은 ρ=0.
    캡션 문장을 "Δ 는 두 워크로드 모두 예약 없음" 으로 좁히거나 합성 위반 칸의 ρ 를 밝힐 것.
(7) 4.1 "예약을 빼면 두 설계 모두 조금 나아진다(같은 지연에서 CAST 0.04, 다시 풀지 않는 설계 0.27%p)":
    CAST 쪽은 kg 에서 한 번 반올림하면 0.03(86행). 또 시드 넷에서는 같은 α=0.575 의 CAST 가 ρ 를 빼면 셋에서 0.05~0.16%p 나빠짐(지연도 0.0~0.4 ms 바뀜) — 본 워크로드만의 서술임을 밝히면 안전.
(8) 3.4 "121 ms 로 무릎점(47 ms)의 2.5배" — 121·47 은 실행 시간 가중, 비 2.5 는 작업당 평균 축(실행 시간 가중이면 2.56 → 2.6).

(10) 4.3 "상한 없음은 위반이 24,993건과 46,354건이고, 최대 동시 실행이 63건과 117건" — 이번 판에서 앞 문장의 α=1 비교(95.65 대 95.97)가 빠져 "과" 뒤 값(α=1)이 무엇인지 문장에 없음.
(11) 서론 543.2·13.6("2025년 연평균")과 3.2 "2025년 MAE 26.10": 모두 평가 구간(1월 8일~) 값. 2025 전체면 543.9·13.65·25.60(2회차와 같음).
(12) 4.2 "227~387건(시드 포함 0.16~0.56%…)": 건수는 본 워크로드만, %는 시드 포함. 시드까지 건수로 쓰면 227~802건(2회차와 같음).
(13) 4.4 Azure ρ=13 문장: "예약 행이 CAST의 절감만 5.20%p 깎아"(무릎점 실행끼리) 뒤에 "다시 풀지 않는 설계가 2.10%p 앞선다"(고정 α 짝) — 두 수의 짝이 다름.
     고정 α 짝 쪽에서는 CAST α=0.5375 가 6.18%p 깎이고, 다시 풀지 않는 설계 무릎점도 0.37%p 깎임("만" → "주로").


════════ 3. 전칭 문장과 받치는 실행 ════════
- "실험한 모든 조건(최대 이용률 43.2%까지)에서 마감을 지키고 상한을 넘긴 배정 없이"(서론): engine=joint 226판 전부 위반 0, 비-_buggy 481판 slo 0. 43.2% 는 ρ0·ρ13 두 판 모두 있음 → 받침 있음.
- "두 워크로드와 모든 예측기에서 위반이 0"(4.2, 네 설계): 4×2×3 = 24칸 실행 모두 있고 0 → 받침 있음.
- "이 위반은 모두 꽉 찬 원 리전에 넣는 규칙에서 났고, 그 순간 다른 리전에는 늘 빈자리"(4.2): 18판 재계산, 정상 시작 위반도 모두 강제 초과 작업이 도는 중에 시작 → 받침 있음.
- "네 벌에서도 … 신뢰구간 모두 0 밖, 대기도 짧다"(4.4): 네 JSON·네 실행 쌍 모두 → 받침 있음.
- "네 주 모두 CAST 가 하한에 더 가깝다"(4.4): 네 주 × 두 설계 파일 → 받침 있음(ρ=3 조건).
- "4.7절의 일곱 회계 모두에서 CAST가 0.26~2.52%p 앞선다"(4.5): 일곱 회계 재채점 → 받침 있음.
- "합성 아홉 조건에서는 여덟에서"(4.6): 아홉 JSON → 받침 있음.
- "표 5 모든 행에서 위반은 0": CAST 실행 전부 0 → 받침 있음.
- "이 이점은 2%p 안이다"(초록 국·영): Azure ρ=0 짝 2.53 이 반례 → 받침 없음(불일치 7·14행).
- "예약을 빼면 두 설계 모두 조금 나아지기 때문"(4.1): 본 워크로드(같은 지연)·Azure 에서는 맞으나 시드 넷 CAST 는 셋에서 반대 → 본 워크로드로 좁혀야 안전(87행 주의).
- "설계 비교는 두 워크로드 모두 예약 없이"(4.1 규칙): 4.4 무릎점 짝·초록 31%·4.7 한계 배출 짝·서론 하한이 ρ=3 → 규칙이 원고 전체에서 지켜지지 않음(불일치 6·13·34·143·189·190행).
