3. 문제 정의

3.1 표기

작업 집합을 J, 리전 집합을 R 로 둔다. 슬롯 길이는 탄소집약도 자료의 해상도에 맞춘 1시간이다.
작업 j 는 출발 리전 o_j, 제출 시각 s_j, 실행 시간 d_j, 지연 예산 L_j 를 가지며 마감은
D_j = s_j + L_j + d_j 다. 리전 r 은 동시에 돌릴 수 있는 작업 수의 상한 cap_r 을 가진다.
스케줄러가 정하는 값은 둘이다 — 실행 리전 r(j) 와 시작 시각 τ_j.

리전 r 에서 시각 t 에 돌고 있는 작업 수를 n_r(t) = |{ j : r(j) = r, τ_j ≤ t < τ_j + d_j }| 로 쓴다.
상한을 넘긴 양이 초과다: o_r(t) = max(0, n_r(t) − cap_r).

작업은 둘로 갈린다. 마감까지 남은 여유가 한 슬롯에 못 미치는 작업, 곧 ⌊D_j − d_j⌋ ≤ ⌊s_j⌋ 인
작업은 제출 슬롯 말고는 시작할 정수 슬롯이 없다. 이를 "미룰 수 없는 작업"이라 부른다.
나머지는 "미룰 수 있는 작업"이다. 합성 워크로드에서 미룰 수 없는 작업은 건수로 59.1% 지만 실행 시간이 초~분 단위라 총 작업시간의
1.3% 에 그친다. Azure 워크로드에서는 반대로 총 작업시간의 51% 가 미룰 수 없는 작업이다(5.2절).

3.2 목적과 제약

마감과 용량을 둘 다 하드 제약으로 두면 해가 없을 수 있다 — 마감이 코앞인 작업이 상한보다
많이 몰리는 순간이 그렇다. 그래서 마감만 하드로 두고, 용량은 초과를 변수로 둔 채 그 초과를
가장 먼저 줄이는 목적으로 쓴다. 목적은 사전식(lexicographic)이다.

  (1)  첫째, 총 초과 시간   Σ_r ∫ o_r(t) dt  를 최소화한다.
  (2)  둘째, 그 안에서     E = Σ_j P ∫_{τ_j}^{τ_j + d_j} C_{r(j)}(t) dt   (총 배출량)
       와                  Λ = Σ_j d_j · ℓ(o_j, r(j))                     (지연 비용)
       의 가중합을 최소화한다. 가중치 α 는 4.4절에서 슬롯마다 정한다.

여기서 C_r(t) 는 리전 r 의 실측 탄소집약도, P 는 작업의 소비 전력(작업당 1 kW 상수, 5.4절),
ℓ(o, r) 은 출발 리전에서 실행 리전까지의 왕복 지연이다. 지연 비용에 d_j 를 곱한 것은 긴 작업이
리전 간 경로를 그만큼 오래 쓴다는 뜻이며, α = 1 이면 (2) 가 정확히 총 배출량이 된다.

제약은 셋이다.

  (3)  s_j ≤ τ_j,  τ_j + d_j ≤ D_j                      ∀ j      — 제출 뒤에 시작하고 마감 안에 끝난다 (하드)
  (4)  ℓ(o_j, r(j)) ≤ L_j                               ∀ j      — 지연 예산
  (5)  n_r(t) ≤ cap_r + o_r(t),  o_r(t) ≥ 0             ∀ r, t   — 용량 (초과는 변수)

식 (4)는 정의역 제한이다 — ℓ(o_j, r) > L_j 인 리전은 애초에 후보에서 뺀다. 본 연구 자료에서는
지연 예산 최솟값(1 s)이 왕복 지연 최댓값(244 ms)보다 커서 이 제약이 한 번도 걸리지 않는다.
그래도 적어 두는 것은, 예산이 더 짧은 워크로드에서는 이것이 공간 이동의 범위를 정하기
때문이다(6.5절에서 네트워크 SLO 상한을 따로 조여 본다).

식 (5)가 선행 연구와 갈라지는 자리다. 용량을 아예 두지 않으면 최적해는 가장 깨끗한 리전으로
몰린다. 용량을 하드로 두면 마감과 충돌할 때 해가 없다. 초과를 변수로 두면 항상 해가 있고,
"용량을 얼마나 어겼는가"가 수식 밖의 사정이 아니라 목적함수 (1)의 값이 된다.

3.3 왜 한 번에 풀지 않는가

식 (1)~(5)를 1년치 전체에 대해 한 번에 풀려면 모든 작업과 1년치 탄소집약도를 미리 알아야 한다.
온라인 스케줄러는 지금 도착한 작업과 향후 24시간 예측만 가진다. 그래서 본 연구는 매 슬롯
"지금 대기 중인 작업 × 리전 × 향후 24개 슬롯"의 문제를 풀고, 지금 시작하는 결정만 확정한다
(롤링 지평). 선행 연구[v1 의 우리 자신 포함]가 공간과 시간을 두 단계로 나눠 따로 풀었던 것과
달리, 여기서는 둘을 한 문제에 넣는다. 그 차이가 왜 중요한지는 6.2절에서 측정으로 보인다.


4. CAST

4.1 개요

CAST 는 예측 단계와 배정 단계로 되어 있다. 예측 단계는 리전마다 향후 24시간의 탄소집약도를
낸다. 배정 단계는 매 1시간 슬롯마다, 아직 시작하지 않은 작업 전부에 대해 (리전, 시작 슬롯)을
한 번에 정하고, 지금 시작하는 작업만 확정해 장부에 적는다. 나머지는 다음 슬롯에 새 예측으로
다시 푼다. 그림 1 이 이 흐름이다. 배치는 예측값으로 결정하되 배출량은 실측값으로 세어, 예측
오차의 대가가 결과에 남도록 했다.

4.2 예측

예측 모델은 리전마다 독립인 2층 LSTM 이며 은닉 크기는 64 다. 과거 168시간의 탄소집약도,
무탄소·재생 전력 비율, 시각·요일·월의 주기 변수, 공휴일 여부를 받아 향후 24시간을 한 번에
낸다. 캘리포니아·텍사스·독일은 풍속·일사량·기온을 입력에 더하고, 향후 24시간의 같은 기상
변수도 출력층에 넣는다 — 이 세 리전은 기상 예보가 아니라 실측값을 쓰므로 낙관적이다(7절).
학습 2021~2023년, 검증 2024년, 시험 2025년으로 연도를 끊었고 스케줄링 실험은 시험 연도
위에서만 돈다. 학습 조건은 표 [LSTM] 에 있다.

예측 모듈은 본 연구의 기여가 아니다. 그래서 기준 예측기와 나란히 놓고 정직하게 적는다(표 3):
24시간 지평 평균 절대 오차는 여덟 리전 평균 26.1 gCO₂/kWh 로, persistence(48.5)와 168시간
seasonal naive(35.7)보다 낫지만 **24시간 seasonal naive(25.3)와는 대등**하다 — 네 리전에서
이기고 네 리전(캘리포니아·프랑스·인도·일본)에서 진다. 이것이 스케줄링 결과에 얼마나 영향을
주는지는 6.2절에서 예측기를 바꿔 가며 잰다 — 결론을 먼저 말하면, [ ]%포인트 안이다.

4.3 결합 롤링 배정

슬롯 t 에서 아직 시작하지 않은 작업의 집합을 Q 라 하자. 미룰 수 있는 작업은 지금 도착했든
전에 도착했든 전부 Q 에 있고, 이번 슬롯에 도착한 미룰 수 없는 작업도 Q 에 넣는다(이들은
시작 슬롯이 지금 하나뿐이지만 리전은 고를 수 있다).

작업 j 의 후보는 (리전 r, 오프셋 i) 쌍이다. i = 0 은 지금 시작(실제 시각은 max(t, s_j)),
i ≥ 1 은 t + i 에 시작한다. 오프셋의 상한은 마감과 예측 지평 중 이른 쪽이다:
h_j = ⌊ min(D_j − d_j, t + H) − t ⌋, H = 24. 미룰 수 없는 작업과, 여유가 한 슬롯 미만으로
남은 작업((D_j − d_j) − t < 1)은 i = 0 만 허용한다 — 이것이 마감 보장이다(4.6절).

후보 (r, i) 의 비용은 정규화한 탄소 항과 지연 항의 가중합에 실행 시간을 곱한 값이다.

  (6)  c_j(r, i) = d_j · [ α · C̃(r, t, i) + (1 − α) · ℓ̃(o_j, r) ]

C̃(r, t, i) 는 t 에 발행된 예측에서 t + i 부터 d_j 동안의 평균 예측 탄소집약도를, 그 슬롯의
지평 안 최댓값으로 나눈 값이고(0~1), ℓ̃ 는 왕복 지연을 행렬 최댓값 244 ms 로 나눈 값이다(0~1).
탄소 항만 슬롯마다 정규화하는 것은, 전 리전이 함께 깨끗한 슬롯에서 탄소 항이 일률적으로
작아져 같은 α 가 슬롯마다 다른 뜻을 갖는 것을 막기 위해서다.

슬롯 t 의 배정 문제는 다음과 같다. x_{jri} 는 작업 j 를 (r, i) 에 두는 변수이고, 후보 (r, i)
가 슬롯 τ 를 덮는다는 것은 그 실행 구간 [시작, 시작 + d_j) 이 [τ, τ + 1) 과 겹친다는 뜻이다.

  (7)  min  Σ_j Σ_{r,i} c_j(r, i) · x_{jri}  +  M_A Σ_{r,τ} o^A_{rτ}  +  M_B Σ_{r,τ≥t+1} o^B_{rτ}
  s.t.
  (8)  Σ_{r,i} x_{jri} = 1                                                      ∀ j
  (9)  Σ_{(j,r,i) 가 (r,τ) 를 덮음} x_{jri} + n_r(τ) ≤ cap_r + o^A_{rτ}           ∀ r, τ ∈ [t, t + H]
  (10) Σ_{미룰 수 있는 j 의 (j,r,i) 가 (r,τ) 를 덮음} x_{jri} + n_r(τ) ≤ cap_r − ρ_r + o^B_{rτ}   ∀ r, τ ∈ [t+1, t+H]
       0 ≤ x ≤ 1,  o^A, o^B ≥ 0

n_r(τ) 는 이미 시작해 τ 에 돌고 있는 작업 수(장부)다. 식 (9)가 물리 용량이고, 식 (10)은
미룰 수 있는 작업이 미래 슬롯을 전부 채우지 못하게 ρ_r 자리를 비워 두는 예약이다(4.5절).
초과 변수 o 의 벌점은 M_A ≫ M_B ≫ 1 로 두어 식 (1)의 사전식 순서를 만든다 — 물리 초과를
먼저 없애고, 다음 예약 침범을, 그 안에서 탄소와 지연을 줄인다. 비용 c_j 는 d_j 이하로 유계이므로 M_B > max_j d_j, M_A = 100·M_B 로 두면 순서가 보장된다 —
합성 워크로드(d_j ≤ 6 h)는 M_B = 12, Azure(d_j ≤ 719 h)는 M_B = 1,438 이다.

식 (7)~(10)은 선형 계획(LP)으로 푼다. 변수를 0~1 연속으로 두고 풀어 모두 정수면 그대로
쓰고, 분수가 있으면 그 α 로만 정수 계획을 다시 푼다. 실측에서 정수 계획이 필요한 슬롯은
전체의 [ ]% 였다(4.6절).

용량 행 (9)(10)은 미래 슬롯(τ ≥ t+1)에 대해 슬롯 단위로 센다 — 슬롯을 조금이라도 덮는 작업을 한 자리로
보는 보수적 근사이며 매 슬롯 다시 풀리므로 확정 시점에 바로잡힌다. 지금 슬롯(τ = t)만은 다르다 —
이번 슬롯에 시작하는 순간들({t} 과 이번 슬롯 도착의 s_j) 마다 한 행을 두고 그 순간에 돌고 있는 작업을
연속 시각 그대로 센다. 그래야 1초짜리 작업 수십 건이 한 시간 자리를 통째로 먹는 가짜 포화가 생기지
않고, 5.4절의 위반 정의와 글자 그대로 같은 자가 된다.

슬롯 t 에 제출되는 작업(⌊s_j⌋ = t)은 슬롯 시작 시점에 모두 알려진 것으로 보고 한 번에 배정한다 —
최대 1시간의 도착 선견이며, 두 알고리즘과 모든 대조군에 같게 적용한다.

풀고 나면 i = 0 인 작업만 확정한다 — 리전과 시작 시각을 적고 장부에 올린다. i ≥ 1 로
배정된 작업은 "계획"일 뿐 확정이 아니며 다음 슬롯에 다시 들어간다. 그래서 어떤 미래 슬롯도
미리 예약되지 않지만, 지금 시작하는 긴 작업이 미래 슬롯을 덮는 것은 식 (9)(10)이 센다.

  Output: (r(j), τ_j) ∀ j
   1: Q ← ∅
   2: for t ← 0, 1, 2, … do
   3:   for each j with ⌊s_j⌋ = t do  Q ← Q ∪ {j}
   4:   for each j ∈ Q do
   5:     h_j ← ⌊min(D_j − d_j, t + H) − t⌋
   6:     if j 가 미룰 수 없음 or (D_j − d_j) − t < 1 then h_j ← 0

4.4 슬롯별 무릎점 α

지연은 예산 안에서도 낮을수록 좋다 — 응답이 빠르고, 리전 간 전송이 줄고, 장애 반경이 작다.
그래서 탄소와 지연은 두 목적이고, 식 (6)의 α 가 둘의 맞바꿈을 정한다. 선행 연구는 이 값을
사람이 고정한다[CASPER, CICS, Caspian]. 그러나 리전 간 격차는 시각마다 다르다 — 옮겨서
얻는 탄소가 큰 슬롯에서는 지연을 더 치러도 되고, 작은 슬롯에서는 그럴 이유가 없다. 같은
상수를 쓰면 한쪽에서는 보수적이고 다른 쪽에서는 공격적이다.

CAST 는 α 를 슬롯마다 정한다. 후보 α ∈ {0, 0.1, …, 1} 열한 개마다 식 (7)~(10)을 풀어
그 배정의 실행 시간 가중 평균 지연 λ̄_α = Σ_j d_j ℓ_j / Σ_j d_j 와 예측 배출량 ē_α 를 얻고, 두 축을 후보들 사이에서 0~1 로
정규화한 뒤 원점에 가장 가까운 후보를 고른다.

  (11)  α* = argmin_α  √( λ̃_α² + ẽ_α² ),   λ̃_α = (λ̄_α − min)/(max − min),  ẽ_α 도 같은 꼴

물리 초과가 생기는 후보가 있으면 초과가 최소인 후보들 안에서만 고르고, 거리가 같으면 작은
α 를 택한다. 이 규칙은 다중목적 최적화의 이상점(utopia point) 거리 기준[Zeleny]이며, 정규화한
곡선의 기하만 쓰므로 사람이 정한 가중치가 필요 없다. 두 축 모두 식 (2)와 같은 실행 시간 가중이다 —
건수 평균으로 재면 1초짜리 작업 한 건이 6시간짜리와 같은 표를 갖게 되어 목적함수와 다른 자가 된다.
지연 축이 퇴화하면(홈 리전 고정처럼 모든 후보의 지연이 같으면) α = 1 로 둔다.

무릎점이 고정 α 보다 나은가는 한 축으로 물을 수 없다 — α = 1 이 탄소의 최솟값이니까. 묻는
방법은 파레토다: 고정 α 열한 개가 그리는 (지연, 배출) 전선 위에 무릎점이 있는가, 아니면 그
위(같은 지연에서 배출이 적은 쪽)에 있는가. 6.3절이 이를 두 워크로드에서 잰다.

4.5 예약 ρ 와 초과

미룰 수 없는 작업은 도착하는 슬롯에 바로 돌아야 하므로 막을 방법이 없다. 슬롯 τ 가 시작될 때
이전 슬롯에 시작해 아직 돌고 있는 작업이 상한까지 차 있으면, τ 에 도착하는 작업은 들어갈 자리가
없다. 식 (10)의 ρ_r 은 그 이월분(carry-over)을 cap_r − ρ_r 로 묶어 매 슬롯 시작에 ρ_r 자리가
남게 하는 예약이다. 현재 슬롯의 도착은 슬롯 머리에서 모두 알므로 τ = t 에는 예약이 필요 없고,
한 슬롯 안에 끝나는 작업은 이월되지 않으므로 예약에 걸리지 않는다. 값은 워크로드에서 계산한다 — 미룰 수 없는 작업만의 리전별
최대 동시 실행 수. 본 연구의 워크로드에서는 리전별 3~4 건이고 최악값 4 를 전 리전에 쓴다.
이 값은 배정 정책에 거의 안 휘둘린다 — 홈 리전 즉시 실행에서 재도 4, CAST 의 공간 배정
위에서 재도 4 다. ρ 를 0 에서 6 까지 바꾼 결과는 6.5절에 있다.

예약이 있어도 초과는 날 수 있다 — 마감이 코앞인 작업이 상한보다 많이 몰리면 식 (9)의 o^A
가 양수가 된다. 그 건수와 시간을 전부 보고한다(6.1절). "용량을 강제한다"가 아니라
"초과를 목적의 첫 항으로 최소화한다"가 정확한 말이다.

4.6 보장과 복잡도

마감 보장은 구성에서 나온다. 후보 오프셋이 D_j − d_j 이하로만 잡히고(4.3절), 남은 여유가
한 슬롯 미만이면 i = 0 만 허용되므로, 마감을 넘긴 배정은 탐색 공간에 없다. 무한 연기도
없다 — 슬롯이 하나 지날 때마다 여유가 정확히 1 줄고 시작값이 유한하므로 유한한 슬롯 안에
i = 0 만 남는다. 초과 변수 덕에 식 (7)~(10)은 항상 해가 있다. 이 셋은 증명이 아니라 구성상
보장(by construction)이다.

식 (7)~(10)의 구조는 작업–(리전, 슬롯) 이분 배정에 구간 덮음 제약이 붙은 꼴이다. 덮음 제약이
없으면 제약 행렬이 완전 단모듈(totally unimodular)이라 LP 완화가 정수해를 낸다[인용]. 덮음
제약이 붙으면 일반적으로는 그 성질이 깨지지만, 실측에서 LP 완화가 분수해를 낸 슬롯은 전체의
[ ]% 뿐이었고 그때만 정수 계획으로 다시 풀었다. 슬롯당 풀이 시간은 평균 [ ] ms, 95백분위
[ ] ms, 최대 [ ] ms 였다(Apple M1 Max, HiGHS [버전]). 1년치 8,592 슬롯이 [ ]분이다.
슬롯당 변수 수는 대기 작업 수 × 리전 수 × 지평이며 실측 최대 [ ]개였다. 작업 수를 2배로
늘렸을 때의 변화는 6.7절에 있다.

4.7 탄소 회계

작업 j 의 배출량은 실행 리전의 실측 탄소집약도를 실행 구간에 대해 적분한 값에 소비 전력을
곱한 값이다. 실측 계열이 1시간 해상도이므로 실행이 걸치는 슬롯들의 평균 강도에 실행 시간을
곱해 근사한다 — 겹침 길이로 가중해 정확히 적분해도 총량은 0.002% 안에서 같다. 소비 전력은
작업당 1 kW 상수다. 상대 비교를 위한 단순화이며, 그래서 배출량 차이는 전적으로 실행 리전과
시각에서 온다. 평균 배출계수를 쓰는 것의 한계(한계 배출, 전송 에너지, PUE)는 7절에 적는다.


2. 관련 연구  (초안 — 인용 번호는 참고문헌 확정 뒤)

탄소 인지 스케줄링은 "언제" 돌릴지와 "어디서" 돌릴지를 바꿔 배출을 줄인다. 선행 연구를
그 두 축과 용량의 유무로 가르면 본 연구의 자리가 드러난다.

시간 축만 다룬 연구. Wiesner 등[W]은 한 데이터센터 안에서 작업을 미루는 것만으로 얼마나
줄일 수 있는지를 독일·영국·프랑스·캘리포니아 전력 자료로 보였고, 자원 제약은 두지 않았다고
스스로 밝혔다. 구글의 CICS[C]는 하루 전에 산정한 가상 용량 곡선(VCC) 하나로 다음 날의
유연한 부하를 시간대별로 묶는다 — 용량이 곧 정책이지만 리전 간 이동은 없다. CarbonScaler[CS]는
한 리전 안에서 작업 하나의 서버 수를 탄소 예보에 맞춰 늘렸다 줄이며, GAIA[G]는 한 리전
클러스터에서 탄소·완료시간·비용의 맞바꿈을 다룬다. 넷 모두 "어디서"를 바꾸지 않는다.

공간 축만 다룬 연구. CASPER[CA]는 웹 서비스 요청을 리전 간에 나누되 서버 프로비저닝 비용과
탄소의 가중합을 쓰고, 그 가중치는 고정이다. Maji 등[M]은 다중 클라우드 CDN 에서 탄소를 보는
전역 부하 분산을 다룬다. 둘 다 작업을 미루지 않는다.

두 축을 함께, 용량 없이. Sukprasert 등[S]은 시간·공간 이동의 상한을 1년치 완전예지로
분석해 공간 이동이 지배적이라고 결론지었다. 그 분석은 리전 용량을 두지 않는다 — 그래서 최적해는
가장 깨끗한 리전 하나로 몰리고, 본 연구 자료에서 그 정책을 그대로 돌리면 작업의 99.75% 가
프랑스로 간다(6.6절). Attenni 등[A]도 자원이 항상 가용하다고 가정한다.

두 축과 용량을 함께. Caspian[CP]은 다중 클러스터 쿠버네티스에서 리전과 시간대를 정수
계획으로 함께 정하고 용량을 하드로 두되 마감은 벌점으로 완화한다. 평가는 24시간 200건이다.
Zanotto 등[Z]은 본 연구와 가장 가깝다 — 리전별 동시 실행 상한 M_j, 작업별 하드 마감, 자체
예측기, 온라인 입장 제어를 모두 갖춘 쿠버네티스 아키텍처다. 평가는 1개월, 1,000건 묶음 반복,
비교 기준은 라운드로빈 하나이며, 상한 M_j 를 어떻게 정할지는 향후 과제로 남겼다. Hall 등[H]은
구글식 집계 부하를 하루 전 계획과 실시간 배치로 시공간 성형하며 확률적 성능 보장을 준다 —
개별 작업이 아니라 집계 부하, 클러스터 넷, 하루 단위다. Lechowicz 등[L]은 작업 하나를 마감
안에 거리공간 위에서 옮기는 온라인 문제(SOAD)에 경쟁비 보장을 주었고, 여러 작업의 자원 경쟁과
데이터센터 용량은 정식화에 없다고 저자가 적었다.

본 연구의 자리. 여러 작업이 리전별 상한을 두고 경쟁하는 온라인 문제에서, 본 연구는 세 가지를
한다. 첫째, 용량을 입장 때 거르는 조건이 아니라 모든 대기 작업이 함께 보는 제약으로 두어
(리전, 시작 슬롯)을 한 문제로 푼다 — 두 단계로 나눠 풀면 예측이 좋아질수록 위반이 느는
역설이 생긴다는 것을 측정으로 보인다(6.2절). 둘째, 탄소와 지연의 가중치를 고정하지 않고
슬롯마다 파레토 무릎점에서 정한다 — CASPER·CICS·Caspian 은 모두 사람이 정한 상수를 쓴다.
셋째, 용량 상한을 상수가 아니라 실험 변수로 두고 쓸어, 시간 이동의 이득과 용량 충돌이 같은
리전에 몰린다는 것을 두 워크로드에서 보인다 — Zanotto 등이 향후 과제로 남긴 "상한을 어떻게
정하는가"에 대한 답이기도 하다. Zanotto 등과는 동시기 독립 연구이며, 본 연구가 더 가진 것은
1년·146,000건 연속 스트림, 탄소 인지 선행 정책 넷과의 같은 회계 비교, 그리고 상한 결정
분석이고, 덜 가진 것은 실제 클러스터 프로토타입이다.

예측. 하루 앞 탄소집약도 예측은 DACF[D]·CarbonCast[CC]가 따로 다룬 문제다. 본 연구의
LSTM 은 그 축의 기여가 아니며, 4.2절에서 기준 예측기와 나란히 놓고 6.2절에서 예측기를 바꿔도
스케줄링 결과가 얼마나 흔들리는지를 잰다.


5. 실험 설정  (초안)

5.1 탄소 자료, 리전, 지연

평가는 8개 리전의 2025년 실측 탄소집약도 1년치 위에서 한다. 자료는 Electricity Maps API 로
1시간 해상도로 받았고[EM], 발전과 설비를 모두 포함하는 전과정 배출계수 체계다[EM-M]. 리전과
전력망 존의 대응은 표 [존] 에 있다 — 각 Azure 리전을 그 리전이 놓인 전력망 존에 짝지었다
[확인: East US(버지니아)에 NYISO 를 쓴 근거, 인도·일본의 존 코드와 추정치 비중].
자료의 1월 1~7일은 1월 8일 프로파일을 반복해 채운 준비 구간이라 예측과 실측이 같다. 그래서
모든 평가는 1월 8일(168시간)부터 연말까지 8,592 시간에서 하고, 그 전에 제출된 작업은 뺀다
(합성 워크로드 146,000건 중 143,200건).

리전 간 왕복 지연은 Azure 가 공개한 8×8 실측 행렬[AZ-L]에서 가져왔다(최댓값 244 ms,
비대각 최솟값 12 ms). 전 구간에서 고정이다 — 부하에 따른 지연 변화는 모델에 없다(7절).

5.2 워크로드 둘

합성 워크로드. 리전당 하루 50건, 1년 146,000건이다. 작업은 지연 등급 k = 1~5 를 가지며 등급
비율은 3:1:1:2:3 이다. 등급마다 지연 예산 L_j 는 범위 안에서 로그균등으로, 실행 시간 d_j 는
로그정규(중앙값·σ)에 상·하한을 두고 뽑는다(표 2). 도착은 현지시각 기준으로 일주기를 가진다 —
k = 3~5 는 13시, k = 1~2 는 02시를 봉우리(σ = 3 h)로 70% 가 주력 시간대에, 30% 가 반대
시간대에 균등하게 온다. 생성기와 시드(42)는 저장소에 있고, 시드를 바꾼 4벌과 등급 비율을
바꾼 4벌(미룰 수 있는 비율 φ = 20~60%)도 같은 생성기로 만들었다(6.5절).

75 백분위(5,100 초) 근처이고, Azure 중앙값은 1,500 초, 95 백분위는 74,400 초(20.7 시간)다.
합성은 5분 이하의 짧은 작업(VM 트레이스는 300 초 해상도라 보지 못한다)을, Azure 는 하루를
넘는 긴 작업을 담는다. 총 작업시간은 Azure 가 합성의 7.8 배라 두 워크로드의 용량 상한은
절대값이 아니라 각자의 기준 피크에 대한 배수로 둔다(5.3절).

5.3 용량은 상수가 아니라 변수다

리전 용량 cap_r 은 본래 설비 규모(서버 수 × 서버당 처리량)에서 와야 하지만 클라우드 사업자는
리전별 설비 규모를 공개하지 않는다. 그래서 본 연구는 용량을 유도하지 않고 실험 변수로 둔다.
단위는 "기준 배정(홈 리전 즉시 실행)의 리전별 최대 동시 실행 수" — 합성 워크로드에서 13 —
이고, cap_r 을 그 0.5 배부터 3 배까지 쓸었다(6.5절). 본문의 대표 지점은 16(1.23 배)이며
설비가 관측 피크를 조금 넘는 상태에 해당한다. 리전마다 자기 피크에 비례해 설비를 두는 이질
용량도 따로 돌렸다. 어떤 정책이든 채점은 이 물리 상한으로 한다 — CAST 가 내부에서 쓰는 예약
ρ = 4 는 채점 기준이 아니다.

  초과 시간      Σ_r ∫ 1[n_r(t) > cap_r] dt (시간).
  필요 용량      정책이 만든 배정의 리전별 최대 동시 실행 수의 최댓값 — 그 정책이 위반 없이
                 돌려면 필요한 상한. 채점 상한과 무관한 절대값이라 정책 간 비교에 쓴다.
  마감 위반      τ_j + d_j > D_j 인 작업 수.
  지연           공간 이동이 더한 왕복 지연의 평균과 95 백분위(ms).
  미룸           τ_j − s_j 의 평균(시간).
  풀이 시간      슬롯당 LP/MILP 벽시계(ms) 평균·95 백분위·최댓값.

1. 서론  (초안 — 숫자 [ ] 는 실험 뒤)

데이터센터가 쓰는 전력이 빠르게 늘고 있다. 국제에너지기구는 2024년 약 415 TWh 였던 전 세계
데이터센터 전력 소비가 2030년 945 TWh 에 이를 것으로 전망하며 AI 를 가장 큰 요인으로 지목했다[IEA].
에너지 사용의 투명성이 규제 대상이 된 이상[EU] 배출을 줄이는 일은 운영상의 과제가 되었고, 이미 가동
중인 인프라에 신규 설비 없이 적용할 수 있는 수단이 필요하다.

배출량을 정하는 것은 소비 전력량만이 아니다. 전력 1 kWh 를 만들 때 나오는 탄소량, 곧 탄소집약도는
그 순간 전력망의 발전원 구성에 따라 달라진다. 본 연구의 여덟 리전에서도 2025년 실측 연평균이 인도
543 gCO₂/kWh, 프랑스 14 gCO₂/kWh 로 40배 벌어지고, 하루 안에서도 캘리포니아는 최댓값이 최솟값의
[ ]배다. 클라우드는 이미 여러 리전에 흩어져 있고 배치 작업은 완료 시점에 여유가 있으므로, 이 격차를
쓸 조건은 갖추어져 있다.

이 격차를 쓰는 연구는 많다(2절). 그런데 리전 용량을 두고 보면 문제가 달라진다. 용량을 두지 않으면
최적해는 가장 깨끗한 리전으로 몰린다 — 선행 정책 하나를 본 연구 자료에 그대로 돌리면 작업의
99.75% 가 프랑스로 간다. 용량을 둔 연구도 있다. 그러나 본 연구가 출발한 자리는 그 다음 질문이다:
용량을 **어떻게** 두느냐가 결과를 바꾼다는 것. 용량을 입장 때 거르는 조건으로 두면 — 각 작업이 제
최선의 슬롯을 따로 고르고, 그 슬롯이 차 있으면 다음 슬롯에 다시 — 예측이 좋아질수록 더 많은 작업이
같은 저탄소 시각을 기다리고, 상한 위반이 늘어난다. 본 연구의 이전 설계가 정확히 그랬다: 완전예지
예측으로 바꾸자 위반이 [6]건에서 [32]건으로 늘었다. 예측을 잘하는 것이 해가 되는 스케줄러는 설계가
잘못된 것이다.

본 논문은 탄소 인지 스케줄링 시스템 CAST 를 제안한다. 매 1시간 슬롯마다, 아직 시작하지 않은 작업
전부에 대해 (실행 리전, 시작 슬롯)을 하나의 선형 계획으로 정한다. 용량은 모든 작업이 함께 보는
제약이고, 상한을 넘기는 양은 숨기지 않고 목적함수의 첫 항으로 최소화하며, 마감은 구성상 보장된다.
탄소와 지연의 가중치는 사람이 정하지 않고 슬롯마다 파레토 무릎점에서 정한다.

기여는 셋이다.
첫째, 결합 롤링 배정(4.3절). 리전만 도착 때 고정하는 분리형 대조군과 같은 비용·같은 상한·같은
예측에서 비교하면, 결합은 배출을 [ ]%포인트 더 줄이고 완전예지에서도 위반이 늘지 않는다(6.2절).
둘째, 슬롯별 무릎점 α(4.4절). 고정 α 열한 개가 그리는 파레토 전선에 대해 무릎점은 [껍질 위 / 위쪽]
에 놓인다 — 사람이 상수를 정하지 않고도 [ ](6.3절).
셋째, 용량이 어디서 무는가(6.4~6.5절). 시간 이동의 이득과 용량 충돌이 같은 리전(캘리포니아)에
몰린다는 것을 보이고, 이것이 용량 상한의 값·리전 간 비대칭·미룰 수 있는 비율·예측 지평·네트워크
SLO·워크로드 종류(합성과 Azure VM 트레이스)를 바꿔도 유지됨을 보인다. 선행 정책 넷은 우리가 정한
상한이 아니라 각 정책이 요구하는 "필요 용량"으로 같은 평면에 놓는다(6.6절).

여덟 리전 1년치 실측 탄소집약도 위에서 CAST 는 배출을 [ ]% 줄였고(기준: 홈 리전 즉시 실행),
작업 [ ]건 전량을 마감 안에 처리했으며, 상한을 넘긴 배정은 [ ]건이다.

Thick lines carry jobs, thin lines data, and the dashed line returns remaining capacity to the LP.

6.6절 문단 초안 (숫자 확정분)
  선행 정책 넷을 원문의 수식과 공개 코드대로 본 연구 자료 위에 다시 구현하고 같은 회계로 채점했다(표 7, 그림 7). 비교의 자는
  둘이다 — 물리 상한 17 에서의 위반 건수와, 상한과 무관한 "필요 용량"(그 정책의 배정이 요구한 리전 최대 동시 실행 수;
  1초짜리 스파이크의 영향을 가리기 위해 시간 가중 99.9 백분위도 함께 적는다). 둘의 순서는 같다.
  절감률만 보면 CASPER(95.3%)와 Sukprasert 공간+시간(96.6%)이 앞선다. 그러나 두 정책이 요구한 필요 용량은 29 와 129 로,
  기준 배정의 피크 13 의 2.2 배와 9.9 배다 — 그만한 설비 없이는 돌릴 수 없는 배치다. CICS 는 홈 리전을 떠나지 않아
  필요 용량이 12 로 기준보다 낮지만 절감은 13.9% 에 그친다.
  v1 에서 "Sukprasert temporal" 로 적었던 행은 홈 고정이 아니라 CAST 의 공간 배정을 물려받은 리전 위에서 시각만 옮긴 값이었다.
